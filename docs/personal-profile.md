## 4. Design Capabilities / 设计能力

说明：以下为与定位双轴对齐的能力方向，对应项目中的工作方式；不设熟练度百分比。

### Industrial Design

关注造型与结构如何被用户理解，以及场景中的视觉呈现。项目中用于产品形态、结构叙事与高质量场景表达；纯建模参数与工程图纸细节不作为对外主叙事。

### UX / UI Design

关注界面层级、状态变化、原型与可用性说明。把交互逻辑落到可点击、可演示的数字触点，便于招聘方快速判断互联网 / UX 相关匹配度。

### Experience Design

关注使用流程、用户旅程与人机交互。在硬件、医疗与 XR 等约束下，梳理多模态与空间中的体验路径，说明用户如何完成关键任务。

### Intelligent Product Design

关注软硬协同与系统策略。在传感、空间或生态相关场景中，把智能逻辑与使用场景写清楚，而不是只展示外观。

## 5. Research Capabilities / 研究能力

说明：以下为研究相关能力方向；具体方法与产出以各 Case Study 为准，此处不虚构研究样本或结论。

### User Research

从场景、痛点、利益相关者与设计目标出发，界定「为谁、解决什么」。在医疗等敏感场景中，强调约束条件下的共情与问题定义（如 TMJ Care 类项目所侧重）。

### Competitive Analysis

能力关注：在概念发散前建立品类与体验参照，支撑差异化判断——待有案例证据后补写。

### User Journey

梳理用户从接触到完成任务的关键节点与情绪/摩擦点。用于医疗佩戴体验、智能装备使用流程与 XR 空间任务等叙事。

### Information Architecture

组织信息层级与内容模块，使流程与界面可扫描。作品集站点 IA 的实践可作侧面说明；项目内 IA 产出待 Case 文案补全。

### Experience Analysis

对照目标与实际路径，分析体验断点、状态缺失与软硬衔接问题，再反哺交互与界面决策。

### Design Strategy

在约束下做方向取舍：何者优先服务用户任务、何者服务技术可行性或商业/评审目标。对外表达「为何这样做」，而非罗列功能清单。
