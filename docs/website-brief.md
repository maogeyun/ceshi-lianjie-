- 一级导航：`Home` · `Works` · `About` · `Resume`

## 1. 网站定位（Positioning）

### 一句话定位

面向互联网与体验设计求职的个人作品集——同时呈现 **工业设计（Industrial Design）**、**UX/UI 设计** 与 **智能产品设计（Intelligent Product Design）** 的综合能力，用完整设计过程证明「从问题到可体验方案」的思维。

### 品牌叙事主线

我在工业设计与智能产品的基础上，关注人与产品、界面、空间之间的交互；用研究、原型与视觉表达，把复杂问题做成清晰、可用的体验。

### 角色标签（首页可用）

- 能力三轴（并列展示，避免只剩单一岗位名）：Industrial Design · UX/UI · Intelligent Product Design
- 求职向补充句（可选）：Seeking roles in UX / Interaction / Product Experience Design

### 定位逻辑

| 现实背景 | 招聘方常见顾虑 | 网站要传达的信号 |
|---------|----------------|------------------|
| 工业设计工程研究生 | 「是不是只会外观 / 建模？」 | 有研究、流程、交互与界面能力 |
| 同时做 ID / UX / 智能产品 | 「定位是否模糊？」 | 三轴并列、项目打标签，叙事统一为「体验与产品」 |
| 项目含硬件、医疗、XR | 「和互联网岗位有什么关系？」 | 每案抽出用户、流程、交互、数字触点 |
| 求职偏 UX / 交互 | 「跨界是否不够专？」 | 作品排序与首页文案可按投递方向微调（见排序方案） |

### 不建议的定位

- 只写「工业设计师」——削弱 UX/互联网求职匹配度
- 只写「UI 设计师」——证据链与差异化不足
- 「什么都会」无主线——招聘方记不住

## 2. 核心目标（Goals）

1. **求职转化（Primary）** — 3–5 分钟内让招聘 / 设计负责人判断是否约面
2. **能力证明（Secondary）** — 2–3 个深度 Case Study：研究 → 洞察 → 概念 → 交互/界面/原型 → 验证
3. **三轴记忆（Tertiary）** — 留下 Industrial Design + UX/UI + Intelligent Product 的清晰标签
4. **信任与联系（Supporting）** — 简历与联系方式易达

### 成功标准

- 首页 10 秒说清：你是谁、三轴能力、适合什么方向
- 任一主推项目 2 分钟看懂：问题、角色、方法、结果
- 不翻找即可打开 Resume 或 Contact

## 3. 目标用户（Audiences）

| 用户类型 | 来访动机 | 浏览习惯 | 网站应对策略 |
|---------|---------|---------|-------------|
| UX/产品招聘与面试官 | 筛人、约面 | 扫首页 + 1 个项目 | 结论先行；Case 摘要栏置顶 |
| 设计负责人 | 看思维与方法 | 精读 1–2 个 Case | 过程完整、有取舍 |
| 设计公司 / ID 相关方 | 看落地与造型质量 | 看视觉与完整度 | 高质量图、结构清晰 |
| 导师 / 学术方 | 看研究与表达 | 读背景与过程 | 保留问题定义与方法 |
| 同行 | 学习 / 转发 | 看亮点 | 叙事清晰 |

**第一用户（默认）：** 互联网 UX / 交互招聘方与设计负责人。  
**兼顾用户：** 工业设计 / 智能产品相关评审与公司（通过项目标签与排序方案覆盖）。

## 4. 用户最希望获得的信息

1. 你是谁、与岗位是否匹配（含三轴能力）
2. 代表作质量（2–3 个深度项目）
3. 你怎么想、怎么做（研究、交互逻辑、取舍）
4. 成果与影响（或诚实的阶段成果）
5. 软硬协同 / 智能产品证据（流程、界面、系统）
6. 教育、技能、经历等可信信息
7. Resume 与 Contact

### 反模式

大段空泛自我介绍、无优先级的项目堆砌、只有效果图没有过程。

## 5. 应突出的能力（Capability Highlights）

与定位三轴对齐，网站反复印证：

| 能力轴 | 对应定位 | 在项目中如何体现 |
|--------|----------|------------------|
| 用户研究与问题定义 | UX / Intelligent Product | 场景、痛点、利益相关者、设计目标 |
| 交互与体验设计 | UX / UI / XR | 流程、旅程、多模态与人机交互 |
| UX/UI 表达 | UX / UI | 界面、状态、原型、可用性说明 |
| 智能产品 / 系统思维 | Intelligent Product | 软硬一体、传感 / 空间 / 生态策略 |
| 工业设计与视觉呈现 | Industrial Design | 造型、结构叙事、场景与渲染质量 |

**相对弱化：** 纯建模参数、纯工程图纸细节 → 附录或折叠，避免淹没体验叙事。

### 三大项目类型速览（排序评估用）

| 项目 | 类型属性 | 更易证明的能力 | 与互联网求职的关联度 | 完成度假设（待你校准） |
|------|----------|----------------|----------------------|------------------------|
| **中电海康 XR** | 硬件 + 软件 / 空间交互 | 多模态交互、UX 流程、软硬协同 | 高 | 若交互与界面叙事完整，优先服务 UX 岗 |
| **CrabClean** | 工业设计 + 智能产品 | 系统策略、智能产品、人机场景 | 中高（需抽出交互与使用逻辑） | 若方案与场景完整，适合做差异化主视觉 |
| **TMJ Care** | 医疗产品 / 工业设计 | 共情研究、约束下体验、工业设计完成度 | 中（需加重旅程与研究） | 若研究与佩戴体验深，适合证明 UX 研究力 |

> 说明：上表「完成度」为策划假设。你选定最终顺序时，请以**实际素材完整度、过程文档、视觉成品**为准微调。

## 6. 作品展示优先级：三套方案（待你选定）

**原则：** 首页精选与 `/works` 列表顺序一致；未选定前文档不锁定单一顺序。

---

### 方案 A — 交互优先（UX / Interaction 求职向）

**推荐顺序：** 中电海康 XR → CrabClean → TMJ Care

| 维度 | 说明 |
|------|------|
| **适合职业定位** | UX 设计师、交互设计师、多模态 / XR 体验、软硬结合产品体验岗 |
| **能突出的能力** | 多模态与空间交互、流程与界面、软硬协同；次位展示智能产品系统思维；医疗研究作补充 |
| **可能存在的问题** | 若 XR 案缺少清晰 UI/流程/你的职责，首屏「互联网感」会空；工业设计造型优势露得偏晚；纯 ID 公司可能觉得「不够工业」 |

**适用条件：** XR 项目有较完整的交互说明、界面或原型、个人贡献可写清。

---

### 方案 B — 智能产品平衡（ID × Intelligent Product × UX）

**推荐顺序：** CrabClean → 中电海康 XR → TMJ Care

| 维度 | 说明 |
|------|------|
| **适合职业定位** | 智能硬件 / 消费电子体验、产品设计师（偏智能）、同时投 ID 与 UX 的「跨界」叙事 |
| **能突出的能力** | 智能产品系统与场景（CrabClean）；再用 XR 证明数字交互与 UX；TMJ 补研究与工业设计深度 |
| **可能存在的问题** | 互联网招聘方若只看第一个项目，可能误判为「纯工业 / 环保装备」；需在 CrabClean 卡片与摘要栏**强标** UX / 人机 / 智能交互，并在首页三轴标签写清楚 |

**适用条件：** CrabClean 视觉与系统叙事最完整，且能明确写出使用流程与智能逻辑。

---

### 方案 C — 研究与共情先行（UX Research / 医疗体验 / 设计深度）

**推荐顺序：** TMJ Care → 中电海康 XR → CrabClean

| 维度 | 说明 |
|------|------|
| **适合职业定位** | 偏研究的 UX、医疗 / 健康产品体验、强调用户洞察与约束下设计的岗位；学术向展示也友好 |
| **能突出的能力** | 深度用户研究、敏感场景共情、体验旅程；再用 XR 接上交互与数字能力；CrabClean 收尾做智能产品广度 |
| **可能存在的问题** | 医疗硬件首屏对「互联网大厂 UX」匹配感弱；若 TMJ 缺少旅程 / 测试 / 洞察结构化表达，会像「只做了外观」；智能产品差异化出现较晚 |

**适用条件：** TMJ Care 的研究过程、用户旅程、设计决策素材扎实，视觉完成度高。

## 7. 内容结构总览

采用 **「少而深」** 结构；导航与 About 已按你的方向确认：

| 导航 | 路径 | 核心内容 |
|------|------|----------|
